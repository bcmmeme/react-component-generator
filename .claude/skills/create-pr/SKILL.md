# create-pr

현재 브랜치의 변경을 GitHub PR 로 만든다. 이 스킬은 `context: fork` 로 서브 에이전트에서 실행되므로 이전 대화를 볼 수 없다. 필요한 정보는 전부 git 과 저장소에서 직접 수집하고, 사용자가 인자로 준 힌트(PR 제목 의도, base 브랜치, draft 여부, 언어)가 있으면 우선 반영한다.

PR 본문의 품질은 리뷰어가 diff 를 열기 전에 "무엇을, 왜" 를 이해할 수 있는가로 정해진다. diff 를 나열하지 말고 변경의 의도를 쓴다.

## 절차

### 1. 사전 점검
- `gh` 로 저장소를 다루므로 `gh auth status` 와 `git remote -v` 로 대상 저장소와 로그인 상태를 확인한다. 인증이 실패하면 원인을 보고하고 중단한다. 다른 계정·토큰을 임의로 쓰지 않는다.
- 현재 브랜치가 기본 브랜치(main/master)면 중단하고 보고한다. 기본 브랜치에서 PR 을 만들 수 없고, 브랜치를 임의로 새로 만들지 않는다.
- `git status` 로 커밋되지 않은 변경이 있으면 PR 에 포함되지 않는다는 사실을 보고서에 적는다. 커밋은 하지 않는다.
- base 브랜치는 인자가 없으면 `gh repo view --json defaultBranchRef` 로 정한다.

### 2. 변경 분석
- `git log <base>..HEAD --oneline` 과 `git diff <base>...HEAD --stat` 으로 범위를 파악하고, 핵심 파일의 diff 를 읽는다.
- 변경이 없으면(base 와 동일) PR 을 만들지 않고 보고한다.
- diff 에서 API 키·토큰·`.env` 같은 비밀 값이 보이면 PR 을 만들지 않고 파일 위치만 보고한다. 값은 출력하지 않는다. PR 은 외부에 보이는 기록이라 한 번 올라가면 회수하기 어렵다.

### 3. 템플릿 언어 결정
규칙은 단순하다. **이 프로젝트(`react-component-generator`)는 한국어, 그 외 모든 프로젝트는 영어**다. 사용자가 인자로 언어를 명시하면(`--lang en`, "영문으로", "한국어로") 그것이 우선한다.

| 대상 | 템플릿 |
|---|---|
| 이 프로젝트 | `references/pr-template-ko.md` (한국어) |
| 그 외 프로젝트 | `references/pr-template-en.md` (영어) |

이 프로젝트인지는 아래 중 하나라도 맞으면 그렇다고 본다. 프로젝트 폴더 이름은 `-leader` 같은 접미사가 붙을 수 있어 쓰지 않는다.
- 저장소 루트 `package.json` 의 `name` 이 `react-component-generator`
- `git remote get-url origin` 의 저장소 이름이 `react-component-generator` (소유자·계정은 무관)

둘 다 확인할 수 없으면 영어 템플릿을 쓴다. 제목과 본문의 언어도 선택한 템플릿 언어를 따른다. 보고서에 어떤 근거로 골랐는지 적는다.

선택한 템플릿 파일을 읽어서 섹션 구조를 그대로 채운다. 해당 없는 섹션은 지우지 말고 "N/A" 로 둔다. 구조가 일정해야 리뷰어가 같은 자리에서 같은 정보를 찾는다.

### 4. 제목과 본문 작성
- 제목은 70자 이내 한 줄. 프로젝트 커밋 컨벤션이 있으면 따른다(기본 `type: 요약`, type 은 feat/fix/refactor/chore 등). 선택한 템플릿 언어로 쓴다.
- 본문은 템플릿의 섹션을 채운다. 변경 사항은 커밋이 아니라 의도 단위로 묶는다.
- 테스트 항목은 실제로 실행한 것만 체크한다. 실행하지 않은 검증을 완료로 쓰지 않는다. 테스트 명령은 프로젝트의 `AGENTS.md`/`package.json` 에서 찾는다.
- 이슈 번호를 알 수 있으면(브랜치명, 커밋 메시지) `Closes #N` 으로 연결한다. 추측하지 않는다.
- 세션 지침에 PR 본문 마지막 줄 attribution 이 지정되어 있으면 템플릿 끝에 붙인다.

### 5. 푸시와 PR 생성
- 현재 브랜치가 원격에 없거나 뒤처져 있으면 `git push -u origin <branch>` 로 올린다. 강제 푸시(`--force`)는 하지 않는다.
- 본문은 임시 파일로 만들어 `gh pr create --base <base> --title "<제목>" --body-file <파일>` 로 생성한다(이스케이프 문제 방지). 인자에 draft 지시가 있으면 `--draft` 를 붙인다.
- 같은 브랜치에 열린 PR 이 이미 있으면(`gh pr view`) 새로 만들지 않고 그 URL 을 보고한다.
- 권한 분류기나 훅이 push·PR 생성을 막으면 우회하지 말고 무엇을 하려 했는지와 필요한 권한을 보고한다.

### 6. 보고
서브 에이전트의 최종 응답이 사용자에게 전달되는 유일한 결과이므로 아래를 반드시 포함한다.

```
PR 생성 완료
- URL: <pr-url>
- 제목: <제목>
- base <- head: <base> <- <branch>
- 템플릿: 한국어 | English (선택 근거: <한 줄>)
- 포함 커밋: N개
- 특이사항: 미커밋 변경, 미실행 테스트, 생략한 섹션 등 (없으면 없음)
```

실패나 중단이면 어느 단계에서 왜 멈췄는지, 사용자가 해야 할 일을 함께 적는다.
